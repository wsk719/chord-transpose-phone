# 防禦性開發與審查專家技能

## 執行指引
當使用者進入程式碼實作、錯誤排除（Bug fixing）或測試編寫階段時，請自動整合以下四大技術護欄：

### 1. 程式碼審查與品質控管
當要求評估程式碼時，請從以下面向給出精簡、條列式的具體建議，並指出具體檔案與行號：
- **安全性與效能**：檢查有無潛在漏洞、記憶體洩漏或不必要的重複邏輯。
- **可讀性與維護性**：變數命名是否清晰、功能拆解是否合適。

### 2. 防禦性錯誤診斷與修復
當使用者提供錯誤訊息、當機日誌（Logs）或回報非預期行為時：
- **根因定位**：分析堆疊追蹤（Stack Trace），主動過濾重複噪訊，明確指出崩潰的檔案、方法與具體行號。
- **治本修復**：修復時不只是解決當下當機，必須加上必要的防禦性設計（如空值檢查、型態檢查、Try-Catch 區塊），並評估是否影響上游既有功能。

### 3. 自動化測試生成
當需要驗證功能或拉高測試覆蓋率時：
- 識別所有條件分支與邊界條件，使用專案既有的測試框架生成測試個案。
- 涉及外部 API、資料庫或系統時間時，必須使用 Mock/Stub 進行隔離。每個測試個案必須包含清晰的安排（Arrange）、執行（Act）、斷言（Assert）三階段。

### 4. 資安盲點與套件防線（新增）
- **嚴禁金鑰外洩**：在生成或修改程式碼時，**絕對禁止 hardcode（硬編碼）任何 API 金鑰、密碼、Token 或個人隱私資訊**。必須強制提醒使用者使用環境變數（如 `.env` 檔案）來載入。
- **拒絕盲目引進外部套件**：當遇到未實作的功能時，優先評估能否用該程式語言的「原生標準庫」來寫。非必要絕不准隨意叫使用者執行 `npm install` 或 `pip install` 引進未知的第三方肥大套件。

## Gotchas（踩過的坑）
- **盲目重寫引入新 Bug**：遇到 Error 錯誤時，嚴禁盲目地重新生成整段程式碼。必須優先進入「診斷模式」找出根因，精準修改。
- **敷衍式錯誤捕捉**：嚴禁直接使用無意義的捕捉（如 try-except pass）來敷衍錯誤，必須給予合理的預設值（Default Value）或拋出可追蹤的自訂異常。
